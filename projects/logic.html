Project 2: Logic Basics

Timeline

January 2026 – February 2026

What this is

This section documents my understanding of programming logic, learned through Python as a tool. The goal was never to memorize syntax but to understand how computers think and how logic becomes code.

Core concepts I learned

Variables

Variables are storage boxes. They hold a value until you change it. The name of the variable does not matter — only the value inside does. Assigning a variable does not create a relationship, it creates a copy.

Conditions (if / else)

Conditions let a program make decisions. Every rule in a real system is essentially an if/else. For example: if a user is admin, allow access. Otherwise, deny. This is the foundation of access control, ticket priority, and incident classification — all of which I built in later projects.

Loops

Loops repeat work without rewriting code. I used loops in every project to process lists of tickets, iterate through knowledge bases, and build menu systems that keep running until the user exits.

Functions

Functions separate logic from interface. Instead of mixing everything in one place, functions let you define a rule once and reuse it. This is how I kept my projects clean and explainable.

Input validation

Real systems must handle wrong input without crashing. I learned to validate every input: check the type, check the range, handle unknown values gracefully. This appears in every project I built.

How I applied this logic

  • AccessGate — role and permission checking using conditions
  • ProcessFlow — business rules using if/elif chains
  • IT Helpdesk — ticket priority logic and status updates
  • Incident Simulator — multi-condition priority calculation
  • AI Nurse Assistant — keyword detection and knowledge base lookup

Honest reflection

I learned logic by building real systems, not by doing exercises. Every concept here was applied directly in a project I can explain and demonstrate. I cannot write complex algorithms from memory, but I can reason about how a system should behave and translate that into working code.
